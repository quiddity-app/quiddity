- The desktop app shares its graph with the user's other devices. [[The shell]] holds a `Peer` from [[quiddity-node]], and puts it on the network when the app starts. [[Device list]]
- There are two replicas on one device, and only one is on the network.
	- [[The UI]] holds its own, in WASM, so typing never waits on IPC. The shell holds the other, which is the device as the network sees it.
	- The UI pushes its edits to the shell a few hundred milliseconds after typing stops. The shell imports them, saves, and sends them on to connected devices.
- Changes from other devices reach the UI as they happen.
	- The shell remembers what the UI is known to have: the snapshot it started from, what it has pushed and what it has been sent. Whatever the graph has beyond that is sent as one update, on a channel as raw bytes, whenever the graph changes.
	- The UI imports it and tells its views at once, as for any change that is not typing. It does not push it back, since the shell has it.
	- Saving records the device in the graph, so a push is followed by a small update that is only that record. It does no harm, but it is wasteful, and a record that is only made when something changed would stop it.
- The UI tells the shell which block is open, and which blocks a push was typed in.
	- That is what drives the publish gate: typing in a block nobody else has open is held back, and goes when the user moves on. [[Publish gate]]
	- It also makes this device visible to the others, who can know it is in a block. [[Presence]]
- Not yet
	- Presence is not shown. Other devices' open blocks are known to the shell and not drawn. [[Presence]]
- Letting two devices meet is done from the Devices page, which calls these.
	- The page shows this device's ID with a copy button, lists the devices the graph records, and takes another device's ID to add. It lists them from the UI's own replica, so a device appears as soon as the shell's graph has it. [[Add a device]]
	- Each device has an ID, which is its endpoint ID. The app gives it with `device_id`, and `quiddity-node id` prints a node's.
	- A device that has the graph lists the other with `allow_device` (`quiddity-node allow` on a node). A blank app has no graph to list anyone in, so `allow_device` trusts the ID until the app closes, and the device it joins through lists it when it connects.
	- A node that lists the app dials it, so only the node needs to be reachable by name. [[Device list]]
- Settings, as environment variables
	- `QUIDDITY_NO_SYNC` leaves the network off.
	- `QUIDDITY_LOCAL` is an address to listen on and nothing else, with no relays or lookup, for two devices on a network or one machine.
- Things worth knowing
	- Saving and sync do not wait for each other. The shell saves when the UI pushes and again a moment after any change, whoever made it.
	- The UI replica starts a new Loro peer ID each session, so each launch adds an entry to the graph's version. A stable ID per device would avoid that, and must differ from the shell's own.
