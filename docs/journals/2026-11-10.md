- Put files in an export, and read them back on import ([#186](https://github.com/quiddity-app/quiddity/pull/186))
	- Put files in the export, and read them back. [[Export and import]] [[Binaries]]
		- `export` writes each file to `assets/<hash>.<ext>`, once for each hash, and says how many it wrote and how many the graph names that this device doesn't have. `import` keeps the files in `assets/` that are named for the BLAKE3 hash of what is in them, and counts the rest. The page for a file already has its `##asset` line in its Markdown, so nothing was added to the entity files and a graph exported before this imports unchanged.
		- Import is strict on purpose. A Logseq graph's `assets/` would otherwise fill the store with pictures nothing refers to by hash, which garbage collection would then have to find.
		- The extension is a convenience and the hash the identity, so two assets with the same bytes share a file, named by whichever the export reached first.
		- Whole files are read into memory, one at a time. Not a problem at the sizes tried, a 70 KB file; it would be for a video.
		- Two mutations checked the tests: dropping the content-hash check fails the import test, and dropping the de-duplication fails the export one.
		- CI's `cargo mutants` found five more that my two checks hadn't: four MIME-type arms nothing exercised (`gif`, `webp`, `avif`, `json`), now one test that lists every type the export knows, written out rather than read back from the code; and a `&&` that was redundant. `Hash` parses a 64-character name only as lower-case hex, so checking for hex digits as well added nothing, and the filter is now just the length.
- Read properties only from a properties block, known by its first line ([#244](https://github.com/quiddity-app/quiddity/pull/244))
	- Step 3 of [[Model redesign]]. A properties block is known by its first line, `parse_properties_block` in [[quiddity-syntax]] reads only its property, tag and `##` lines, and [[quiddity-core]] keeps the rest as `EntityInfo::stray` and flags it. [[Entity]] [[Block]]
		- A first block that starts with prose is now an ordinary block even if it holds property lines, and one that starts with a property and goes on with prose is a properties block with stray lines. The old rule needed every line to be a property.
		- A link typed in a properties block's prose still makes its entity when the block is saved, though it is no backlink. Not fixed here; worth deciding when the UI step gives that block its own editor.
		- Tags in the Tags column and in queries are still read from every block. Step 4 replaces them with `##tag`.
- Give the fuzz jobs 15 minutes rather than 5 for a cache miss ([#245](https://github.com/quiddity-app/quiddity/pull/245))
