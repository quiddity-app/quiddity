- Delete files nothing refers to any more, when it is safe to ([#189](https://github.com/quiddity-app/quiddity/pull/189))
	- Deleting files nothing refers to any more: `quiddity-node gc`. [[Binaries]] [[Compaction]]
		- The rule is the design's, made precise. A file goes only if the graph doesn't refer to it, it has been unreferenced for the grace (30 days), and it was first seen unreferenced at a version every active device has since stored. The last clause stops a file going while a device that hasn't heard it was dropped is about to refer to it. When the rule can't be applied (no compaction point, a blank replica, an unreadable record) it deletes nothing.
		- iroh-blobs has no public delete: its own comments say to rely on its collector, which removes whatever isn't marked live. So the node opens the store with a collector told to keep everything stored but the doomed files. That is the dangerous shape (a mistake in what to keep deletes everything), so it checks afterwards that every file it meant to keep survived, and two mutations (protect everything, protect nothing) are caught by the tests.
		- My first test run failed on a doomed file that was still there: the empty file. The store treats it as built in, so it is always present and never listed. The deletion was right and the test wrong, and now says so.
		- Two of my own test bugs cost time. Versions built in fresh graphs don't compare (they count different peers' edits), which made a correct rule look broken. A proptest failure from that wrote a regression file I deleted rather than committed, since it recorded my mistake and not the code's.
		- Five mutations on the rule (no version check, no grace, no compaction point meaning go, ignoring damaged lines, a later sighting replacing the first) are each caught.
		- The sandbox's disk filled again, from the mutation rebuilds' test binaries. The first sign was a linker bus error, not a message about space.
		- Not done: nothing runs it automatically, and the app can't. A node that is serving must be stopped to collect; making that unnecessary needs the store opened with a collector from the start.
		- A hole in that safety net, found by reading the CI's mutation result on the export instead of my own tests: a damaged `##asset` line protects the file whose hash it begins with, but `Hash` parses lower-case hex only, so one written in capitals protected nothing and its file was deleted. A test written first showed the file removed; the hash is now lowered before it is read.

- Make `##tag` and `#tag` the same tag, and a tag a link ([#246](https://github.com/quiddity-app/quiddity/pull/246))
	- Step 4 of [[Model redesign]], in part. [[tags]] is now the page for tags: `#a` and `##tag:: [a]` are the same, a tag is a link, and `tags::` is an ordinary property. [[quiddity-core]] reads a block once (`read_block`) for properties, tags and links.
		- A tag is still held in the index as a valueless inline property, so queries and qualifiers needed nothing new. It isn't a property in the model; a later step could give tags a type of their own.
		- `type` stays until journals (step 5) and property entities (found by name) no longer need it. [[type]]
		- A block that is nothing but tags is a properties block when it is an entity's first child, so `update_text` declines it and the index is rebuilt. Typing a lone `#tag` as a first block costs a rebuild.
