- The graph's device list now says who may connect, and authorising a device is a graph edit. [[Device list]]
	- It decides who may connect, not whose edits are kept.
	- Authorising one device lets it connect to every device that gets the entry, which is the model, and means any member can add one.
	- Listed devices are dialled too, with a delay that backs off, and a handshake timeout, since dialling a dead address otherwise hangs.
- Published the documentation as a static site on GitHub Pages. [[Publishing]]
	- The same UI the desktop app embeds now builds around a graph on disk when `QUIDDITY_STATIC_GRAPH` is set. [[Static build]]
	- CI imports `docs/` with `quiddity-node`, builds the UI around the result and deploys it.
	- The site is the UI showing its own documentation, so this page is the real thing, not a mock-up.
- Things worth remembering
	- Panes only render in the browser, so the HTML is a shell and the content arrives after load.
	- Edits on the site live in the page and are lost on reload.
	- Actions in workflows must be pinned to hashes (zizmor insists), and the first push to the workflow was red for exactly that.
- Held back typing that nobody can see. [[Publish gate]]
	- `Peer::edited` saves at once but sends only if another device has the block open, or once the edit is over.
	- Saving must not wait, so "the graph changed" and "send the changes" are separate signals.
- The repository moved to `quiddity-app/quiddity`, and the crate metadata now says so.
- Things worth remembering
	- The UI runs `View` in the browser and the shell holds the native graph, so nothing in `View` can reach a `Peer`. The gate will be driven by commands from the UI to the shell, once the shell runs a peer. [[Presence]]
- A fuzz failure in the block syntax: an inline property could mean something different alone than with text after it. [[Testing]]
	- Nested links in a value can read past the closing parenthesis, and a stray `]]` after it was enough to close one that the property's own text leaves open.
	- The first reading now only finds where the value ends, and the text up to there is read again until it reads as exactly itself. The crash inputs are fuzz seeds.
- Things worth remembering
	- A property test with a generator for nesting never found it, in 20,000 cases. The fuzzer did, twice. The regression is a named example and the seeds.
	- Written as a loop, the fixed point timed out under mutation testing. As a recursion a flipped test overflows the stack at once.
- Added search: an action strip above the main pane, with a panel on Cmd/Ctrl-K, and pages found by title. [[Search]] [[Title matching]]
	- The panel is a list of facets, each a section that fills in when it is ready, so that full text and, later, embeddings can arrive slowly without holding up the rest.
	- Titles are matched as an IDE does: letters in order, and a capital must start a word, so `QD` finds `Quiddity Design`.
	- The matcher is in `quiddity-view` and reaches the UI through `quiddity-wasm`, so it is tested and mutation-tested natively.
- Added full-text search of blocks as the panel's second section. [[Text search]]
	- BM25 over every block, with the last query word allowed to be unfinished and a bonus for words together and in order.
- Things worth remembering
	- The first mutation run on the BM25 code missed twenty mutants, every one in arithmetic. The tests only compared orderings, and an ordering survives swapping a division for a multiplication. Pulling the formulas into small functions and checking them against values worked by hand fixed it. [[Testing]]
	- A test of the matcher's own oracle was wrong before the code was: emoji aren't letters, so a "word" made of one has no tokens. The generator now keeps them for the explicit examples.
	- A single-word query must not get the phrase bonus: the words are trivially together, so it would only scale every score. [[Text search]]
	- Not built, on purpose: aliases in the title facet, an actions facet, and ranking across sections. [[Search]]
