- Found why the graph tests were flaky in CI, and fixed it in the app rather than in the tests. [[The UI]]
	- CI's `ui` job failed three times in a day (two merge-queue runs and `main`), each time on a different test in `graph.spec.ts` and each time waiting 20s for a canvas that never came. The other 93 tests passed, and the 20s wait added on 4 November had not cured it. It reproduced locally at about four runs in five hundred.
	- `/` is `Home`, which redirects to wherever the graph's `home` setting says once the graph has loaded. The sidebar's links start working at about the same moment. A link followed in the gap started a navigation, and the redirect, arriving a moment later under load, took it over; the click had been delivered and the page ended up on the journals.
	- `Home` now notes links followed before its first redirect and doesn't redirect over them. Only the first redirect can race, so a later visit to `/` (Back, say) still redirects.
	- A named test in `pages.spec.ts` follows the Graph link the moment it is drawn and makes the graph page slow, which holds the race open: it failed twelve runs in twelve without the change and passed twelve in twelve with it.
	- Not covered: a navigation that is not a link (Cmd-K search, a keyboard shortcut) made in that same gap would still be overwritten. It is a few milliseconds wide, and nothing has hit it.
