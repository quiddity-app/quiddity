- Moved CI's Rust builds onto mbx, a shared build cache, including the Tauri shell.
	- The `app` job runs the shell's `cargo clippy` and `cargo test` through mbx, with the WASM build for the UI going through it too.
- Things worth remembering
	- mbx 1.29 runs build scripts through a `#!/bin/sh` wrapper. On Ubuntu that is dash, which drops environment variables whose names aren't valid shell identifiers.
	- tauri passes its core permissions to `tauri-build` as cargo metadata keyed `core:path`, `core:event` and so on, which reach it as `DEP_TAURI_CORE:PATH__...`. With the wrapper they go missing, nothing complains, and `tauri::generate_context!` panics with `SetPermissionNotFound core:path:default`. macOS's `sh` is bash, which keeps them, so it passes locally.
	- The `app` job sets `MBX_BUILD_SCRIPT_EXECUTION=0` so build scripts run directly. Compilation is still cached; build-script runs are not. Remove it when mbx stops using `sh` for the wrapper.
- Filled out the documentation for the UI. [[The UI]]
	- Pages for the UI, editing, undo, rendering, properties, links to nowhere, renaming, the graph view and running the app, and journal entries for the days they were built.
	- The pages describe what is on `main`. Work still in pull requests is not documented until it lands.
- Cached the fuzz builds without mbx. [[Testing]]
	- Fuzzing already ran on `main`, but mbx bypassed nearly every compile under cargo-fuzz's sanitizer flags (`unknown-codegen-option`), produced no reusable target state and so saved nothing. Building on `main` was never going to help.
	- The fuzz job now skips mbx (the setup action's `mbx` input) and saves `fuzz/target` with `actions/cache` on pushes to `main`; pull requests restore it. The key includes `fuzz/Cargo.lock` and `mise.toml`, which pins the toolchain.
- Starting a peer on the network is now one call in the node crate, ready for the app to use. [[Device list]]
	- `serve` binds an endpoint, serves the peer and dials the listed devices, and `save_on_change` saves a few hundred milliseconds after changes. Both were in the command line, and the app needs them too.
	- `Peer::trust` lets a device in for now without listing it. A blank app needs it to let in the device it joins through.
- The app shell now runs a peer. [[App sync]]
	- `Session` owns the `Peer`, and the UI's pushed edits are saved and sent on to other devices.
	- There are commands to read the device's ID and to let another device in, but no screen for them yet.
	- Changes from other devices are saved but not yet shown by the UI until it restarts.
- Things worth remembering
	- Tauri's system libraries were missing in the sandbox. `apt-get update` first, then the packages `scripts/doctor.sh` names.
