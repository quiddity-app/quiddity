- Graph view moved from SVG to a canvas. [[Graph view]]
	- The SVG was slow, an element per node and line, moved on each step of the layout. The canvas, the nearest-node hit-testing, repainting once per frame and not while hidden all come from the Logseq viewer. I did not take its stepped simulation loop: d3's own timer runs one step per frame already.
	- The cost was that nodes were links on the page. They are now a visually hidden list of real links beside the canvas, which keeps keyboard and screen reader use, and is not positioned so it adds nothing per step. Focusing a link highlights its node.

- Fixed a dragged node jumping away from the pointer on the canvas. [[Graph view]]
	- d3-drag reports a drag in the subject's own coordinates, and the subject was the node, whose position is in the graph's space, not the canvas's pixels. So the node was placed using an offset from the wrong space and then followed the pointer from there. The subject is now the node's place in canvas pixels. A test checks the node is where it was grabbed, relative to the pointer, and not just that it moved.
- Designed types for properties: [[Meta-properties]] and [[Queries]]. Nothing is built yet; the pages say so.
	- `##key(parameter)` lines in a property entity's properties block: `##value-type`, `##values`, `##applies-to`, `##cardinality`, `##transitive`, `##inherits`, `##inverse` and `##symmetric`. A fixed set in a namespace of its own, and never a reason to reject text.
	- `##values` is what a value may refer to and `##applies-to` what may have the property: the other way round from RDF's domain and range, which is why neither name is used.
	- Queries use [[jj]]'s operators: `&`, `|`, `~`. A value in `#key(…)` is itself a query, so `#parent(#type(country))` works.
	- They replace `value-type::`, `form::` and `cardinality::`, which only the code's own tests used. `form` goes: a list is always allowed, and only its order sets it apart.
	- To build next: parsing in [[quiddity-syntax]], then schemas, effective properties and the evaluator in [[quiddity-core]], then inverse lists and inherited values in the UI.
- Built the reading half of [[Meta-properties]] and [[Queries]] in [[quiddity-syntax]]: `##key(…)` lines, and a query parser and formatter. Nothing acts on either yet.
	- The meta-property line scanner finds the closing parenthesis by skipping escapes, keys, quoted names and links exactly as the query parser reads them. Fuzzing found two places they disagreed (a form feed between terms, and an escaped operator before a quote). The new `query` fuzz target checks that they agree.
	- A parameter can't end in a bare backslash, which would escape the `)`; `format_meta_line` adds a space before the `)` when one does.
- Built the meaning of [[Meta-properties]] and [[Queries]] in [[quiddity-core]]. The UI doesn't show any of it yet.
	- Schemas come from `##` lines over the built-in ones. `value-type::`, `form::` and `cardinality::` are no longer read, and `form` is gone: a list is always allowed.
	- Effective properties are worked out when the index is built, repeating until nothing changes, so cycles are fine and are flagged. An inherited or transitive value records the entity it is written on, not the one it came through, because a value can arrive by several routes and the order in which it is found would otherwise decide.
	- A missing value is a cardinality flag only where `##applies-to` says the entity should have the property; without it, there's no saying which entities should.
	- Checked against oracles: transitive closure and inverses against reachability worked out step by step, and queries against an evaluator over the written text. The cost on a large graph is not measured.
