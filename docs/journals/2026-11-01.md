	- The `actions/cache` of `fuzz/target` restored fine but cargo still recompiled every dependency, so a restored directory was not enough. rust-cache keys on rustc and the lockfile and prepares the target directory for reuse, as the Pages build already relies on.
	- It runs after the nightly install, with `RUSTUP_TOOLCHAIN=nightly` on that step only, so that its key sees the nightly cargo-fuzz builds with rather than the stable mise provides. Only pushes to `main` save.
	- I did not find why the plain restore recompiled; if rust-cache also rebuilds, turn on `CARGO_LOG=cargo::core::compiler::fingerprint=info` for one run to see what cargo thinks is dirty.
