- Swapped the fuzz build cache to rust-cache. [[Testing]]
	- The `actions/cache` of `fuzz/target` restored fine but cargo still recompiled every dependency, so a restored directory was not enough. rust-cache keys on rustc and the lockfile and prepares the target directory for reuse, as the Pages build already relies on.
	- It runs after the nightly install, with `RUSTUP_TOOLCHAIN=nightly` on that step only, so that its key sees the nightly cargo-fuzz builds with rather than the stable mise provides. Only pushes to `main` save.
	- I did not find why the plain restore recompiled; if rust-cache also rebuilds, turn on `CARGO_LOG=cargo::core::compiler::fingerprint=info` for one run to see what cargo thinks is dirty.

	- It shows this device's ID with a copy button, lists the devices the graph records, and takes another device's ID to let in. Until now the commands for this existed and nothing called them.

	- A made-up device in the memory backend lets the browser tests check it. The populated list has no browser test, because the made-up graph records no devices.
- A device can now say how it stands with the others: alone, offline, behind, synced or present. [[Sync status]]
	- Out of date is not "the versions differ", because saving records the device in the graph and does not send it. It is what this device lacks, or has held back on purpose.
	- Each connection remembers what its peer is known to have, and the state is worked out from those when asked.
