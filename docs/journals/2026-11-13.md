- Keep a graph in one SQLite file ([#320](https://github.com/quiddity-app/quiddity/pull/320))
	- The graph is one [[SQLite]] file, `graph.quiddity`, holding the snapshot and the endpoint key. [[Storage]]
		- The file is untrusted input: `application_id`, layout version and an exact schema are checked, and connections are defensive. Extending a table means changing its `CREATE` statement and the layout version together, with a conversion.
		- It is created 0600 because the key is in it. Copying it to another machine copies the key, which the planned rework of device IDs is meant to fix.
		- Journal mode is `DELETE` on purpose, so it stays one file at rest.
	- `quiddity-node snapshot FILE` is what the static build publishes, in `mise run docs` and the Pages workflow. `QUIDDITY_STATIC_GRAPH` now names that file, not a directory. [[Static build]]
	- Rebased over #265 (durable saves, and recording only what is already stored), whose behaviour now lives in SQLite. [[Storage]]
		- Durability and atomicity are one transaction with `synchronous=FULL`, which replaces the temporary, rename and directory flush. The `.bak` file is the previous generation, row 2 of `snapshot`, written in the same transaction, and `load` falls back to it. A claim still records only the `durable` version.
		- `key()` reads without a write lock and only writes when the key is absent, because a write lock on every call let a reader block it. The ported failure test found that.
	- Rebased over the recovery screen (#265), whose `Store::set_aside` now moves the whole file aside as `graph.quiddity.damaged-<time>`, with its journal (SQLite pairs a journal with a file by name, so one left behind would be rolled back into the next file of that name). [[Recovery]]
		- The device keeps its identity: the key is salvaged from the damaged file, through a read-only connection so that what is kept is exactly what was found, and carried into the new one. A file too damaged to give it up means a new key.
		- A file with a key and no graph means "no graph" (`Missing`), and `init` fills it, so the ID can be asked for before the graph is made, as before. The file is built under another name and linked into place, so two first users agree and nobody sees it half made.
		- Not run here: the app's recovery test, which I changed to expect the one file. It needs Tauri's system libraries.
	- CI's mutation run found four missed mutants in the schema check and key code, which were redundant code rather than missing tests. [[Storage]]
		- The schema check compares only each statement's `sql`, which already names its kind and name, instead of three conditions two of which the third implies. A test now refuses a file with the right number of tables, and the right names, that are not ours.
		- The open flags are joined with `union` instead of `|`: the bits are disjoint, so OR and XOR are the same and a mutant of it can't be told apart.
		- Making the key logs whether or not it won the race: a count of rows inserted only chose whether to log, which nothing can observe.
	- Not done yet: blobs (`blobs/`, which is iroh-blobs' own redb store) and `unreferenced-blobs.txt` are still beside the file, and `-g` is still a directory. Moving blobs in needs our own storage under iroh-blobs' transfer, and is the next change.
	- The app has its own `Cargo.lock`, updated for `rusqlite`. Its tests were not run here, since it needs Tauri's system libraries.

- Add a blob store for iroh-blobs that keeps whole blobs in the graph's file ([#330](https://github.com/quiddity-app/quiddity/pull/330))
	- A blob store on [[SQLite]] for [[iroh-blobs]] keeps and serves whole blobs, in `crates/node/src/blob_store.rs`, and nothing uses it yet. [[Storage]]
		- It relies on `MemStore::from_sender` being `pub`, which is not a documented extension point, so an iroh-blobs upgrade can break it. `TempTag::new` says it is for store implementations, which is some comfort. The notes are in `crates/node/AGENTS.md`.
		- A `Scope` can't be made outside iroh-blobs, so every batch is global, and temp tags protect nothing. No tags are kept, and a stream or a path can't be imported: nothing reads them.
		- Tested against `MemStore`, with data that doesn't repeat. Mutation testing found the gaps, and the CI job that runs them had twenty minutes, about 60 mutants, so a store this size came in two pieces. (The job has an hour now.)
	- The file's layout is 2, for the `blob` table, and layout 1 is upgraded on opening. [[Storage]]
	- Next: taking a blob in from another device (`ImportBao`), then moving `Blobs` onto this store, which removes the collector-based `sweep` and the ledger file, and makes `-g` the file.
	- `irpc` is a direct dependency with its default features off: they enable a certificate stack (`rcgen`, `x509-parser`, `asn1-rs` and more) that this crate has no use for. The app has its own `Cargo.lock`, which CI builds with `--locked`, so a new dependency means running `cargo fetch` in `apps/app/src-tauri` too, and checking `cargo metadata --locked` in both places.
