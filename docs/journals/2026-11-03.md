- Gave each CI job its own build cache. [[mbx]]
	- The merge queue's rust job was failing in setup, with no log: restoring the shared 3.5 GB cache ran the runner out of disk. Every job had shared one cache key, so each restored whatever tree a job had saved last.
	- The setup action's new `cache` input names the cache, by default the job's; mutation testing shares the rust job's, as it builds the same tests. It goes in mbx's cache generation, since that is also in the prefix a miss restores from.
	- Deleting the runner's unused SDKs first was tried and dropped: the runner already had 84 GB free, and deleting them took nearly two minutes a job.
	- The old shared caches (keys starting `linux-x64-mbx-v1-target-`) are no longer read. They count against the repository's 10 GB until GitHub evicts them after a week unused, or they are deleted by hand. Check the new caches' sizes after the first runs on `main`.
- Tried pairing two real app instances, on virtual displays. [[App sync]] [[Add a device]]
	- A local instance could not dial anything, because with no address lookup a device can only be dialled where it is told. `QUIDDITY_PEERS` says where, as `ID=ADDRESS`, and the dialler uses it even in local mode.
	- The Devices page works in the real app: it shows this device's ID, lists the devices in the graph, takes an ID, and shows the shell's reason when an ID is wrong.
	- Pairing failed all the same: the second instance was not blank. The UI made today's journal in its empty replica on load, so it had history the first device's compacted graph could not sit under ("behind the peer's history"). [[Compaction]] [[The UI]]
	- A replica that has joined nothing (`View::is_blank`, `isBlank` in WASM) is now left alone: `Graph.begin()` makes today's page only once there is a graph, on load or when the first updates arrive. The memory backend has `?blank` to play such a device, and `e2e/remote.spec.ts` checks it. It is still the case that a first-run app makes its own graph, so a second fresh device cannot join it: the app wants a create-or-join choice at first run.
	- The blank replica was still being spoiled: the shell exports a snapshot of its graph for the UI, and a Loro document that has exported a snapshot ignores a compacted one afterwards, so the first device's snapshot was held back (`NotApplied`) and the connection closed with nothing sent. `Graph::snapshot` of a blank replica now comes from a throwaway document.
