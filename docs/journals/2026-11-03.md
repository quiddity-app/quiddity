- Gave each CI job its own build cache. [[mbx]]
	- The merge queue's rust job was failing in setup, with no log: restoring the shared 3.5 GB cache ran the runner out of disk. Every job had shared one cache key, so each restored whatever tree a job had saved last.
	- The setup action's new `cache` input names the cache, by default the job's; mutation testing shares the rust job's, as it builds the same tests. It goes in mbx's cache generation, since that is also in the prefix a miss restores from.
	- Deleting the runner's unused SDKs first was tried and dropped: the runner already had 84 GB free, and deleting them took nearly two minutes a job.
	- The old shared caches (keys starting `linux-x64-mbx-v1-target-`) are no longer read. They count against the repository's 10 GB until GitHub evicts them after a week unused, or they are deleted by hand. Check the new caches' sizes after the first runs on `main`.
