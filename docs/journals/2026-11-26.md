- Hide empty leaf pages in the graph view, and start its options closed ([#578](https://github.com/quiddity-app/quiddity/pull/578))
	- [[Graph view]]: new option, "Empty leaf pages", off to begin with, and the options panel starts closed.
		- `View::connections()` marks each node `empty`; the UI filters on it in `filterConnections` (`lib/graph-filter.ts`), which has its own Node-only spec.
		- Leaves aren't looked for again after hiding one: the page that linked to it may become an orphan, which the orphan option then hides.
- Keep the graph file in write-ahead logging mode ([#583](https://github.com/quiddity-app/quiddity/pull/583))
	- Graph files use write-ahead logging; [[Storage]] now says `-wal` and `-shm` sit beside an open graph, and that a graph should be moved or copied only when closed.
		- `places.sqlite3` is unchanged: it is a small file of the device's own and was never promised to be one file.
- Save the updates since the last save, not the whole snapshot ([#584](https://github.com/quiddity-app/quiddity/pull/584))
	- [[Storage]] now describes a snapshot plus an update log, and layout 6.
		- A layout-5 file is converted by gaining an empty `update_log`; its snapshot is the base. Older builds refuse a layout 6 file.
		- Tests that mean a fold call `Store::write(graph, true)`, because `save` decides by size and tiny test graphs always fold.
		- Next person: folds still rewrite the whole snapshot, so a graph whose edits are a large fraction of its size gains little.
- Let devices be named and removed from the device list ([#586](https://github.com/quiddity-app/quiddity/pull/586))
	- [[Device list]]: devices can be named and removed from the Devices page.
		- `Graph::name_device` and `remove_device` in `quiddity-core`; naming an unlisted device does nothing, since an entry with no record would be read as no device.
		- A device that saves again lists itself again, and keeps its name: Loro keeps a mergeable map's contents under its key. Removal is for devices that are gone, not a lock-out, and a device that hasn't received the edit still lets it in.
		- The UI has no Remove for this device's own row. The made-up graph records no devices, so the page has no browser test; `quiddity-core` and `quiddity-view` test the behaviour.
