- Update the index in place for typing in an ordinary block ([#205](https://github.com/quiddity-app/quiddity/pull/205))
	- Updated the index in place for typing in an ordinary block. [[Performance]]
		- Andrew asked for the incremental index that [[Performance]] had as its next step. The question was how much of it could be done safely: the index is derived from entities' names and properties, from links in every block, and from `id` properties, and effective properties are worked out over the whole set.
		- Prose can only change its own backlinks. Names, properties, schemas and effective properties are read from roots and properties blocks, and nothing else uses backlinks or block-reference ids except the queries in `quiddity-view`. So `Index::update_text` takes a block's old backlinks out and puts its new ones in, in document order, and declines anything wider (a root, a properties block, an `id` property, an unknown block). The caller builds the index again when it declines. [[quiddity-core]]
		- The view patches the one block's text in the corpus rather than reading the structure again, and logs the first text of each block edited so the index hears about it even if the corpus is brought up to date twice first. `View::work` counts scans and builds, because an in-place update that quietly fell back to a rebuild would give the same answers more slowly, and nothing else could notice. [[quiddity-view]]
		- Typing in an ordinary block now costs 2 ms for the first read afterwards natively and 1 ms in the WASM build, with no scan and no build, where it was 80 and 110. Typing in a properties block or a name, or making or moving a block, still builds the index again (about 100 ms).
		- A property test compares a long-lived index with one built afresh, backlinks as vectors; a second compares whole views after random edits, now including each entity's page and references. Mutations of the new code were each caught by a test.
		- An earlier measurement of 80 ms for the first read after typing in WASM was my script typing in an entity's first block, which is its properties block. That is the rebuild case, correctly.
