- Started on [[Binaries]] with the store for their bytes. [[quiddity-node]]
	- Decided with Andrew: iroh-blobs for transfer; an asset is a block described by `##` lines; every device keeps every blob; the UI reads bytes through a Tauri command into object URLs; exports carry the blobs so the Markdown can refer to them.
	- `Blobs` wraps iroh-blobs' filesystem store in `blobs/` beside `graph.loro`, with `put`, `get` and `has`. Nothing calls it yet, and nothing in the graph refers to a blob, so no stored graph changes.
	- iroh-blobs 0.104 needs iroh `^1`, which is what we have. Default features are off, which leaves out its RPC layer; the transfer step will want the protocol and will turn on what it needs.
	- Not done: removing blobs. Anything added is tagged and kept, which is the policy until garbage collection is built.
- Gave a binary its description in the graph: one `##asset(hash, mime, size, name)` line. [[Binaries]]
	- An asset is an entity with that line in its properties block, so it already has a name, can have properties, and is embedded by a link. [[Meta-properties]]
	- A single line, not one per part, because the parts mean nothing alone and a half-edited set of lines would be worse than one bad line. The name comes last because it is the only free text.
	- `##asset` is the one meta-property meaningful off a property entity; any other still is flagged there. A property entity with `##asset` gets the existing unknown-meta flag.
	- The hash is validated as hex and lower-cased, but not looked up: the graph can name bytes this device does not have yet.
	- A property test round-trips a line through the meta-line parser with names full of what a parameter treats specially. Removing the escape for `)` fails it.
- Made the "+ Add a block" button outline on hover rather than filled. [[Developer guide]]
	- Andrew asked for `hover:border-slate-200` in place of the hover fill. A transparent border at rest means the outline appears without moving the text.
- Made `[text](destination)` links work for entities, blocks and the app's own pages. [[Links]]
	- Wanted so the docs site's Quiddity page can link to the actual graph, not the page about it, and to the source on GitHub. [[Quiddity]]
	- `[the library]([[Loro]])`, `[a point](((id)))` and `[graph](/graph/)` are all Markdown links whose destination says where they go. The parser needed one change: `(((id)))` hid its reference behind the link's own parenthesis. [[Syntax]]
	- Block references still cannot be shown, so a link to one opens the entity holding the block (`View::follow_block_ref`). Scrolling to the block is the next step. [[Block references]]
	- Only the app pages `/graph/`, `/all/`, `/journals/` and `/devices/` are allowed by path, so untrusted text cannot send the app anywhere else. Next's `Link` adds the base path. [[Rendering]]
- Named the UI's colours. [[Design language]]
	- Every colour is now a CSS variable with a light and a dark value in `globals.css`, exposed to Tailwind, and components use those names. The `dark:` pairs and palette colours in the components are gone, so a theme is one value each.
	- Two differences came with it, because the names can't spell the odd pairs: the table's secondary cells and blockquotes share one secondary text colour (dark was a mix of slate 300 and 400), and the "from" text in inherited properties is the muted colour (it was slate 400 on a light page, which is hard to read). A table's header rule is the hairline, as its rows are.
	- This starts bringing the app to a written design, one stacked PR at a time. Next are a shared button, field and error line.
- Moved blobs between devices. [[Blob transfer]]
	- A peer given a store (`Peer::set_blobs`) now offers its blobs on iroh-blobs' protocol and fetches the ones the graph names that it lacks, from whichever connected device has them. `quiddity-node serve` opens the store, so the headless node keeps everything.
	- Access is the device list, asked on every blobs connection, before anything is read. Pushing into a store is off. A test with a device the graph doesn't list fails if the check is removed.
	- Both devices have to list each other. I lost a while to this: the fetch from the device that had dialled failed with `connection lost`, and I first took it for an addressing problem. Connecting by ID worked; the dialled device was refusing a device it had not listed, which is the gate doing its job. The test setup now admits both ways, as pairing does.
	- Not done: the app doesn't keep a store, `sync` doesn't fetch, and nothing yet writes an `##asset` line or puts bytes in. The shell commands are next.
- Made a large graph faster to start, to edit and to search. [[Performance]]
	- Andrew's graph has 3,150 pages (journals included) and a 3.3 MB `graph.loro`, and the app was slow to start and stalled after each pause in typing. I built a made-up graph of that size (`crates/view/examples/scale.rs`) and measured before changing anything.
	- Parsing was 23 ms of a 630 ms index build. The rest was asking Loro for blocks one at a time, and every whole-graph answer (the index, the All entities table, each text search) did that again for itself.
	- `Graph::scan` reads the tree in one call and `scan_reusing` takes the text it already has. `View` keeps the result, and an edit says what it changed: typing one block, creating or moving blocks, or anything. [[quiddity-view]]
	- Natively, the first query after typing went from 560 ms to 80 ms, `summaries` from 620 to 180, and `search_text` from 450 to 60. In the WASM build run in Node, which is nearer what the app does, the first read after typing went from 470 ms to 110 and `search_text` from 560 to 120, but `summaries` only from 670 to 400 and start-up from 650 to 570: reading every block once is the cost of starting, and handing thousands of rows to JavaScript is most of what is left of `summaries`.
	- The All entities table draws 200 rows and more as the end is reached; at 3,000 rows it drew them all on every revision. [[All entities]]
	- A property test checks that a view edited for a while answers like one made afresh from the same graph. It fails if typing stops saying which block it changed. A bulk read is checked against the one-at-a-time reads in the tree model test.
	- For the next person: the numbers are native, not browser, and the incremental index is the next step, with the rest in the page. Not run: `cargo mutants` over the change, which CI does.
