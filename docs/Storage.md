- What a device keeps on disk, and what it works out again.
- The [[Loro]] document is the only source of truth.
	- Text is stored in Unicode NFC. [[Unicode normalisation]]
	- A graph on disk is a directory, made by `quiddity-node init`. The graph is one [[SQLite]] file in it, `graph.quiddity`, holding the graph's snapshot and this device's endpoint key. [[quiddity-node]]
		- Blobs and `unreferenced-blobs.txt` are still beside it, for now. Planned: they join the file, so that a graph is one file to copy.
		- The file's `blob` table and the store that serves it to [[iroh-blobs]] are built and tested (`blob_store`), but nothing uses them yet. The layout is version 2 for that table, and a file of version 1 gains it when opened.
		- Whole blobs can be kept in the file and read back, in pieces as they are asked for. Taking a blob in from another device piece by piece is not built yet, and a file over 1 GB is refused: that is SQLite's limit on one value.
		- A directory from before, with `graph.loro`, `graph.loro.bak` and `device.key`, is converted the first time it is opened, and those files are kept with `.migrated` added to their names, and the backup becomes the previous generation. Delete them once the graph opens. The key is in `device.key.migrated`.
	- Saving writes the whole snapshot in one transaction that is flushed to disk before it counts as done, so a crash, even a power loss, leaves the previous snapshot. The one it replaces is kept as the previous generation, and loading falls back to that if the current one can't be decoded, and the app shows a [[Recovery]] screen if that fails too. Saves are serialised. A save records this device in the graph's device list, and compacts what it writes. What it records is what the snapshot held *before* this save, never what it is about to write: other devices act on the record at once, by dropping history up to it, so a write that then failed would have left them ahead of this device. The record lags one save; the history kept doesn't. [[Compaction]]
	- The file is one file at rest: it uses a rollback journal rather than write-ahead logging, so there is no `-wal` or `-shm` beside it. A second process that opens it waits a few seconds and then reports that it is busy.
	- The file holds a secret, so it is created readable by its owner only, and it must not be published or shared as it is. `quiddity-node snapshot FILE` writes the snapshot alone, which is what [[Static build]] publishes. Copying the file to another machine copies the endpoint key with it, which [[Identity]] and [[Copied graphs]] are designed to fix and which is not built.
	- Starting again after a graph can't be opened sets the whole file aside as `graph.quiddity.damaged-<time>`, every byte of it, and makes a new one. The endpoint key is carried over if the damaged file is readable enough to give it up, so the device keeps its identity; if not, the device gets a new one. A file with a key and no graph is a device that has no graph yet. [[Recovery]]
	- The file is treated as untrusted, because a graph may be copied from somewhere else. [[SQLite]]
		- It must carry Quiddity's `application_id` and a layout version this build knows, and its schema must be exactly ours: a trigger, view or table we didn't make refuses it.
		- Connections run in SQLite's defensive mode, with triggers, views and schema-defined functions turned off. Loading also runs `quick_check`.
	- [[The shell]] keeps its graph the same way, in the app's data directory, or wherever `QUIDDITY_GRAPH` says. It saves after each batch of updates from the UI.
- Blobs, the bytes of [[Binaries]], are kept by hash in `blobs/` beside the graph's file, in an [[iroh-blobs]] store. They are not derived and not in the document. `unreferenced-blobs.txt` beside them is the node's record of when it first saw each file that nothing refers to, for deleting them.
- Everything else is derived.
	- The index, of names and aliases, properties, links and how each resolved, is rebuilt from the document in memory and never synced or stored. [[quiddity-core]]
	- Full-text search reads every block when asked, from the text the view keeps. [[Text search]]
	- What costs time at start and after an edit, and what is planned about it. [[Performance]]
- Planned, not built
	- The device key moves out of the graph's directory, which gains a graph ID and a node ID, and the app keeps a map of where its graphs are. [[Identity]] [[Copied graphs]]
	- A snapshot plus an append-only log of updates, compacted now and then, so that a save doesn't rewrite everything. The shell's `AGENTS.md` says when that will be needed.
	- The derived indexes and full-text search in SQLite tables, which can be rebuilt from the document at any time and are never synced.
