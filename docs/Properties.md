alias:: property

- A property is a `key:: value` line, and a tag is a `#key` anywhere in running text, which is a property with no value for now. Both are read from a [[Block]]'s Markdown, which is the source of truth. A `(value)` after a tag is ordinary text. [[Syntax]]
	- An [[Entity]]'s own properties are in its properties block, its first child, and only there: a `key:: value` line in another block has no effect and is flagged. [[Block]]
	- A block's `type` property is its type. [[type]]
	- A property's own page, the entity named for its key, lists its uses under the references, grouped by entity and with each value as written. In the [[Graph view]] it is joined weakly to each entity that has the property and each entity those values link to.
	- A property with no value is written `key::`. `#key` is a tag, which is a link to an entity and not a property. [[tags]]
- One value or several
	- Two `tag:: a` and `tag:: b` lines are two instances of `tag`, with one value each.
	- `steps:: [a, b, c]` is one instance holding an ordered list.
- Property entities
	- Every key can have an entity that defines it (a property entity): the only entity with that name, found as a link to the name alone would find it, so an alias counts and so do case and spacing. Nothing marks it: no `type`, only the name. The built-in ones are documented that way: [[type]], [[alias]], [[favourite]] and [[title]].
	- If nobody has made one, the key has a virtual entity, as a name linked to does: it is in [[All entities]] and the [[Graph view]], has a page, and the page lists who uses the key. Writing to it makes the entity. [[Links to nowhere]]
	- If two or more entities have the name, the property has no entity to define it, and a `##` line on either is flagged as having no effect. Two devices that each make one leave two, and nothing merges them, since entities share names on purpose: rename or delete one.
	- A property entity describes the property in prose, and can give it a schema.
	- It can be renamed. The old name stays as an alias, so the key still finds it. [[Renaming]]
- Schemas
	- A property entity says how its property's values are read, and how it relates entities, with [[Built-in properties]]: `##value-type`, `##values`, `##applies-to` and `##cardinality` for what a property holds, and `##transitive`, `##inherits`, `##inverse` and `##symmetric` for how it relates entities.
	- Value types: `text`, `number` (a double), `boolean` (`true`, `false`, `yes` or `no`), `date` (an ISO 8601 date), `datetime` (RFC 3339, with an offset) or `ref`. More will come, such as `blob`. [[Binaries]]
	- A property nobody has described is text, with any number of values. A value may always be a list.
	- References: for a `ref` property, bare text is a name, so `type:: person` means `type:: [[person]]`. [[Links]]
	- A `ref` property's value is its items, written with or without brackets: `knows:: Jane, [[Smith, John]]`, `knows:: [Jane, [[Smith, John]]]` and `knows:: [[Jane]], [[Smith, John]]` are the same, in the page and in queries. Bare text is split on commas outside `[[…]]` and trimmed, so a name with a comma in it is written in brackets. A quoted or escaped comma splits too, as quotes and escapes are gone by then.
	- Any other property shows the links written in its text as links: `note:: met [[Jane]] at lunch`.
	- Quiddity's own properties have built-in schemas, so a new graph needs nothing written into it first. A property entity's meta-properties override them.
	- A schema can't reject anything: the text is what it is. A value that doesn't fit is flagged instead.
- In the UI
	- When a block isn't being edited, its properties are text, `key::` in bold and then the value. [[Rendering]]
	- A property's key goes to the property's entity. If there is none yet, the key is a link that looks like any other key, and following it makes one with an empty block to describe it in. Shift-click opens it at the side. Making it is one step of [[Undo]].
- How it works: the view reports each property with where it is written, in UTF-16 units, and with the ID of the entity that defines it, so the UI never parses the text itself. [[quiddity-view]]
