- How the code is kept tidy: the Rust has `cargo fmt` and clippy, and `apps/ui`'s TypeScript has ESLint. [[The UI]]
	- `mise run lint:ui` checks it and `mise run fmt:ui` fixes what it can. `pnpm ui lint` and `pnpm ui format` are what they run.
- One tool: [[ESLint]]
	- [[Prettier]] runs inside it, so a formatting difference is a lint error and `--fix` mends it. There is no separate formatter to keep in step.
	- The rules are `eslint-config-andrewaylett`, the same set as aylett.co.uk: `typescript-eslint` with type information, `unicorn`, `import`, `react` and its hooks, and the Next.js plugin. `apps/ui/eslint.config.mjs` adds Quiddity's own choices.
	- Prettier's settings are in `apps/ui/.prettierrc`: semicolons, single quotes and trailing commas everywhere.
- Where it runs
	- CI: the `typecheck` job runs it after `tsc`, because the type-aware rules need the types of the generated `lib/wasm`.
	- pre-commit: a hook runs `pnpm ui format` when a UI file changes.
	- `mise run check` includes it.
- Rules that are off, and why
	- Each has its reason beside it in `eslint.config.mjs`. They are deliberate, not oversights: a rule is turned off when the code does it on purpose.
	- `react-hooks/refs` and `set-state-in-effect`: handlers read the latest state from a ref written during render, because they outlive a render.
	- `no-non-null-assertion`: `noUncheckedIndexedAccess` is on, so `!` is how a lookup that must succeed is written.
	- `require-await`, `no-empty-function` and `no-unnecessary-condition`: backends share one interface, and some have nothing to do or nothing to await.
	- `unicorn/prefer-global-this`: the page's own globals are declared on `Window`.
	- The Playwright specs also allow untyped values from `evaluate`.
- Not built
	- Only `apps/ui` is covered. `scripts/*.mjs` and the Playwright config are not yet linted with type information, and nothing lints the Tauri shell's JavaScript, since it has none.
	- Some of the rules turned off above could come back one at a time, with the code they flag fixed.
- Rust
	- `cargo fmt` formats it and clippy lints it, over the whole workspace, the Tauri shell included: every crate has `[lints] workspace = true`, so the set is in one place, `[workspace.lints]` in the root `Cargo.toml`.
	- Lints are `warn` in the manifest, so that an unused variable doesn't stop a build while editing, and `-D warnings` makes each an error. `mise run lint` and CI both pass it.
	- The set is clippy's default groups plus `pedantic`, a few `rustc` lints (`unused_qualifications`, `unused_lifetimes`, `single_use_lifetimes`, `let_underscore_drop`, `rust_2018_idioms` and others), and some restriction lints picked one by one: `unwrap_used`, `dbg_macro`, `todo`, `unimplemented`, `clone_on_ref_ptr`, `allow_attributes_without_reason`, `absolute_paths` (a path of more than three segments is imported with `use` rather than written at each reference site) and a few more.
	- `unwrap_used` is for production code. `clippy.toml` lets `#[test]` functions unwrap, and test targets that unwrap in helpers say so with `#![expect(clippy::unwrap_used, reason = "…")]`, which fails if it stops being needed. Shared test modules use `allow`, because only some of the binaries that include them unwrap.
	- Prefer `#[expect]` to `#[allow]`, and always give a reason.
	- The `cast_*` lints are on, and a cast says what happens when the value doesn't fit rather than being allowed: `u8::try_from(x)` with `expect` where the range is known, `unwrap_or` or `saturating_*` where a clamp is right, and an error where the value comes from outside. A count as a float goes through `u32` (`as_f64` in `quiddity-view`'s search), because `usize` has no lossless conversion to `f64`.
	- A public function that returns a value and has no side effect gets `#[must_use]` (`must_use_candidate`): calling it and ignoring the answer is a bug, and the attribute is how the compiler knows. It is boilerplate on every getter, which is the cost of having it say so.
	- To discard a value that has a destructor, usually a `Result`, write `drop(…)`: `let _ = …` drops it just the same, and `let_underscore_drop` asks for it to be said. A guard that must live to the end of the block is bound to a named variable instead, such as `_guard`.
	- Format into a `String` with `write!(…).expect("…")` rather than `push_str(&format!(…))`, which clippy flags. `write!` returns a `Result` because a `Display` impl may fail, and `expect` says so where `let _ =` would hide it.
	- Pedantic lints that are off, and why (each has its reason beside it in `Cargo.toml`): `too_many_lines`, `similar_names`, `items_after_statements`, `option_option`, `unnecessary_wraps`, `needless_pass_by_value` and `assert_is_empty`, which are judgement calls; and `missing_errors_doc` and `missing_panics_doc`, which would put a section on every internal function.
	- Not turned on: `missing_docs`, `unreachable_pub` and the `cargo` group, which were hundreds of findings in a workspace that isn't published.
	- CI uses the toolchain `mise.toml` pins, which is newer than the MSRV, so it can know lints an older `rustc` doesn't. `assert_is_empty` is one: clippy before 1.100 warns that the name in `Cargo.toml` is unknown. Treat the pinned toolchain as the one that decides, and don't add a lint to the manifest without running it.
